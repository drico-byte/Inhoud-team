Setting up on a new machine

Everything needed to go from a fresh clone to a working pipeline. Roughly twenty minutes, most of it waiting for installers.

Two things the repository does not contain

Textbooks and curriculum PDFs are deliberately kept out of git and must be copied across by hand — step 4. Nothing can be profiled without them.

1

Clone the repository

It is private, so sign in first if this machine has never authenticated.

PS> gh auth login
PS> git clone https://github.com/drico-byte/Inhoud-team.git

Clone it wherever you keep work. Avoid a OneDrive-synced folder — the pipeline writes constantly and sync will fight it.

2

Install what the pipeline needs

Four things, and two of them are not Python packages.

PS> python -m pip install pyphen spylls
If PowerShell says pip or python is not recognised

Python is installed but not on PATH, which is the Windows default. The python -m pip form above avoids the problem. If python itself is not recognised either, try the launcher instead:

PS> py -m pip install pyphen spylls

And if neither is recognised, Python is genuinely not installed on this machine:

PS> winget install Python.Python.3.12

Close PowerShell and open it again after installing Python, or the new PATH will not be there and you will get the same error. Then go back and run the install line above.

Tesseract does the OCR, and it needs the Afrikaans and orientation language data — tick afr and osd during installation, they are not included by default.

PS> winget install UB-Mannheim.TesseractOCR

Poppler turns PDF pages into images for the OCR.

PS> winget install oschwartz10612.Poppler

If either package name has changed, find it with winget search tesseract or winget search poppler. Both must end up on PATH — the next step checks and will tell you if they are not.

3

Run the setup script

This is the step that makes the clone into a working project, and it is easy to skip because nothing obviously fails without it.

PS> cd Inhoud-team; python bin\opstel.py

It links the content standard into .claude/skills/ so Claude Code can discover it, links the project's memory notes to where Claude reads memory, creates the folders for the source documents, and reports anything missing.

Why it cannot be skipped

The standard lives in skills/ and clones fine, but the link that makes it discoverable is deliberately not in git — it is a machine-specific path. Without this step Claude works without the standard and without any of the project's accumulated rulings, and the output looks plausible while ignoring every one of them.

Run it again whenever something stops working, and after ever moving the folder.

4

Copy the source documents across

Two folders, by hand, from a stick or a share. The folder names and structure matter — the profiler is pointed at paths inside them.

bronne/Intersen/   textbook PDFs17 files
kaps/dokumente/intersen-gr4-6/5 files
kaps/dokumente/senior-gr7-9/9 files
kaps/dokumente/fet-gr10-12/17 files

Both parent folders already exist — step 3 created them empty — so you are dropping files in, not building paths.

Check the counts when you are done:

PS> (Get-ChildItem bronne -Recurse -File).Count
PS> (Get-ChildItem kaps\dokumente -Recurse -File).Count

You want 17 and 31.

5

Confirm it all works

Run the setup script once more. Every line should read ok.

PS> python bin\opstel.py

The one line that may not say ok, and that is fine: the Afrikaans spelling dictionary. Spelling is a warning-level check, so the gate runs normally without it and simply notes that spelling was not checked.

Then ask the pipeline where a finished lesson stands. It should report that the lesson is approved rather than erroring:

PS> python bin\hardloop.py --vak "Natuurwetenskappe en Tegnologie" --graad 4 --subonderwerp "Sterk raamstrukture" --les 1
6

Before writing anything

Two rules that are not obvious from the code and are expensive to learn by breaking.

  • Only the profiler may read a textbook. It emits numbers — page counts, word volumes, register statistics. The planner and the writer see the curriculum plus those numbers, and refuse a textbook however the offer is framed. This is what makes the work independently created, and the git history is the evidence.
  • The runner names the next step. Run bin\hardloop.py for a lesson and it tells you which agent to launch, with the exact input and output paths. Copy those paths into the brief rather than typing them, and check afterwards that the report actually landed.

CLAUDE.md carries these for Claude itself and loads automatically. README.md has the full explanation — the pipeline order, the four human approval points, and the boundary with the layout team.

Scratch files for the OCR are written outside the repository, by default to C:\temp\wolkskool-scratch. Keep them off OneDrive and out of the repo; override with the WOLKSKOOL_SCRATCH environment variable.
If a step fails, paste what it printed to Claude rather than guessing — the setup script's output names the exact problem.
