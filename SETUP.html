Setting up on a new machine

An installer does the whole thing. You clone, double-click, and drop two folders in. Ten minutes, most of it waiting.

The whole job

1
Clone the repository

It is private, so sign in first if this machine never has.

PS> gh auth login
PS> git clone https://github.com/drico-byte/Inhoud-team.git

Anywhere you keep work, but not inside a OneDrive-synced folder — the pipeline writes constantly and sync will fight it.

2
Double-click the installer
install.bat

In the folder you just cloned. It asks for administrator rights, then installs everything and checks its own work. Safe to run as many times as you like.

3
Copy the documents from SharePoint, then run it once more

The textbooks and curriculum PDFs are deliberately not in git, so they are the one thing the installer cannot fetch. It will tell you exactly which folders are empty.

—

What the installer does for you

  • Python, if it is not already there, and the two packages the gate needs.
  • Tesseract and Poppler, which do the OCR and the page rendering.
  • The Afrikaans language data — a tickbox in the Tesseract installer that is very easy to miss, so it is downloaded directly rather than trusted.
  • The links Claude Code needs so it can find the content standard and the project's accumulated rulings. This is the step that costs you silently if it is skipped.
  • A real test — it runs the pipeline against an already-approved lesson and tells you whether the whole chain works.

It refreshes PATH itself. Normally a tool installed a moment ago is still "not recognised" until you open a new terminal. The installer re-reads PATH after each install, so you do not have to.

If anything is still wrong at the end it lists exactly what, and running it again picks up from there — it skips whatever already worked.

The documents you copy by hand

Folder names and structure matter — the profiler is pointed at paths inside them.

bronne/Intersen/   textbook PDFs17 files
kaps/dokumente/intersen-gr4-6/5 files
kaps/dokumente/senior-gr7-9/9 files
kaps/dokumente/fet-gr10-12/17 files

Both parent folders already exist once the installer has run, so you are dropping files in rather than building paths.

If they came from OneDrive, let them finish downloading

Synced files can be placeholders that only download when opened. If the installer reports fewer files than expected, that is usually all it is — wait, then run it again.

If the installer cannot run — doing it by hand

The Python packages

PS> python -m pip install pyphen spylls

If PowerShell does not recognise pip or python

Python is installed but not on PATH, which is the Windows default. Try the launcher:

PS> py -m pip install pyphen spylls

And if neither is recognised, Python is not installed at all:

PS> winget install Python.Python.3.12

Close PowerShell and open it again afterwards, or the new PATH will not be there and you get the same error.

The OCR tools

Tick afr and osd during the Tesseract installation — they are not included by default.

PS> winget install UB-Mannheim.TesseractOCR
PS> winget install oschwartz10612.Poppler

If a package name has changed, find it with winget search tesseract or winget search poppler.

The project's own setup

This links the content standard and the memory notes into the places Claude Code reads.

PS> python bin\opstel.py

Proving it works

PS> python bin\hardloop.py --vak "Natuurwetenskappe en Tegnologie" --graad 4 --subonderwerp "Sterk raamstrukture" --les 1

It should report an approved lesson rather than an error.

—

Before writing anything

Two rules that are not obvious from the code and are expensive to learn by breaking.

  • Only the profiler may read a textbook. It emits numbers — page counts, word volumes, register statistics. The planner and the writer see the curriculum plus those numbers, and refuse a textbook however the offer is framed. This is what makes the work independently created, and the git history is the evidence.
  • The runner names the next step. Run bin\hardloop.py for a lesson and it tells you which agent to launch, with the exact input and output paths. Copy those paths into the brief rather than typing them, and check afterwards that the report actually landed.

CLAUDE.md carries these for Claude itself and loads automatically. README.md has the full explanation — the pipeline order, the four human approval points, and the boundary with the layout team.

OCR scratch files are written outside the repository, by default to C:\temp\wolkskool-scratch. Keep them off OneDrive; override with the WOLKSKOOL_SCRATCH environment variable.
If a step fails, paste what it printed to Claude rather than guessing — the output names the exact problem.
