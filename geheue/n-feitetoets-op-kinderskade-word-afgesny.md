**1 October 2026.** The fact check on a Grade 6 lesson about children's rights
was terminated by a content filter the moment it turned to the governing
statute's definitions of kinds of harm to children. It had written **no report**,
so the entire check was lost.

**Why:** nothing about the task is improper — it is an accuracy check on a
published-curriculum school lesson — but verifying those entries pulled it into
generating long stretches of explicit statutory text, which it never needed in
order to answer the narrow question.

**How to apply.** Two things in the brief, and the second one is general:

1. **Verify by citation, not by reproduction.** Ask for the verdict, the specific
   distinction tested, and the provision checked against; a short quotation where
   one word is decisive, never the definition in full. Ask for a plain, clinical
   register throughout.
2. **Tell every long check to write its report early and update it as it goes.**
   A partial report on disk beats a complete one that never got saved. This is
   worth doing for any long agent run, not only ones at risk of a filter.

Expect this wherever a lesson is about harm, safety or abuse — which is a large
part of Life Skills in every grade. Check for a written file before concluding
nothing happened: see [[n-agent-wat-faal-kan-sy-werk-klaar-he]], and
[[veiligheidslesse-lewer-die-ergste-foute]] for why these checks matter most.

## My own fix for this opened a worse hole: an incomplete report signs off

**7 October 2026.** The mitigation I adopted after the earlier deaths — *tell every long
check to write its report early and keep updating it* — works. A weekly service limit
killed three agents mid-task, and the fact check had a report on disk instead of nothing.

**But sign-off tests only two things about a report: that its verdict says approved, and
that it is newer than the draft. It never asks whether the report is finished.** So an
early report that happened to carry a clean verdict when the agent died would be
accepted, and a lesson whose check never completed would ship as checked. The stub that
actually landed held **one** item where the full round held fifty-two — and it blocked
sign-off only because its verdict happened to read *needs a person*. That was the
verdict's luck, not a guard.

**I made that more likely, not less.** Before the mitigation, a killed check left no file
and the gap was loud. Now it leaves a plausible file. A fix that converts a loud failure
into a quiet one is a bad trade even when the thing it fixes is real.

**How to apply, until a completeness guard exists:**

1. **Brief every checker to write its early report with a deliberately non-clean
   verdict**, and to set a clean one only in the final full rewrite. An unfinished check
   must never be able to say approved.
2. **Count the items before signing anything off**, and compare against what the previous
   round on that lesson held. A fifty-item check that comes back with six is a killed
   agent, not a clean lesson.
3. **Overwrite a stub completely on the re-run** and tell the new checker the file on disk
   is a stub, or it may anchor on it.

Related: [[n-agent-wat-faal-kan-sy-werk-klaar-he]] — the mirror case, where a killed agent
had in fact finished. Both say the same thing: **the agent's exit status tells you nothing
about the file; go and measure the file.** On this same kill a writer had completed its
revision and its record in full and lost only the hand-back, while the check that reported
writing a report had written a stub.
