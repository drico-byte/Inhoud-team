# HTML-span ↔ Inhoud-span: navrae (one shared, tracked list)

**This file is how the two teams talk.** The HTML team writes a row for anything in the V2 text it thinks may be
wrong; the content team answers in the same row. Both teams read it at the start of every session (each team's
`CLAUDE.md` says so). Set up 2026-11-18 by the operator: before this, the list existed but nobody on the content
side was told to read it, so nothing was answered.

## How to use it

- **Status** is one of: `oop` (waiting for the content team) → `beantwoord` (the content team answered in the
  *Antwoord* column) → `toegepas` (the HTML team rebuilt the lesson from the answer, or confirmed nothing changes).
- **Content team:** for each `oop` row, write your answer in *Antwoord*, put the date, and set `beantwoord`.
  - If the V2 text must change, **reissue the lesson** (new `json_sha256` in `manifest.json`) and say so in the
    answer. A reissue is the only thing that changes the HTML; we never reword V2 text ourselves.
  - If the wording is intended, say "bedoel so", so we close it.
- **Content team, writing to the HTML team:** add a row at the bottom with the next `N` number. A notice ("Les 12 is
  reissued") is fine. Anything that would change how the HTML team works (its look, what it draws, a ruling, its
  process) must say **`voorstel`**: it is a suggestion for the operator, and the HTML team acts on it only after the
  operator approves it (operator, 2026-11-18).
- **HTML team:** never edit an *Antwoord*. Add new queries at the bottom with the next number and status `oop`.
  When an answered row is rebuilt or closed, set `toegepas` and note the delivered file in *Antwoord*.
- Under rule 3 every wording below is reproduced in the HTML **exactly** as V2 has it. Nothing here was changed by us.
